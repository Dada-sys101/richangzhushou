## 2. 目标与非目标

### 2.1 目标

1. 建立一套移动优先、暖白背景、柔和紫色主色的 Daily Assistant 视觉语言。
2. 固化用户端四个根导航：首页、记录、计划、我的，并为桌面端提供可扩展的导航适配。
3. 让首页优先服务“快速记录”和“今天要处理的事项”；问候区同一视觉区域内显示日期、星期、城市和天气，小猫作为轻量插画，不单独占一行。
4. 增加 AI 对话入口和对话页面的设计边界：支持消息互动、输入、快捷建议和 Proposal/草稿确认，但不越过用户确认写入正式业务数据。
5. 统一二级页面的列表、详情、编辑、复杂详情、设置五类排版，并保持返回、焦点、底部操作区和窄屏适配一致。
6. 让管理端继续使用 Element Plus，以左侧导航、顶部上下文、主表格和右侧详情抽屉形成稳定后台骨架。
7. 保留设计 token、主题扩展、紧凑/舒适密度、header/filter/status/action slots、桌面 max-width 和双栏布局的后续演进空间。

### 2.2 非目标

- 不在本系列中重做后端架构、数据库、API、认证、同步、Service Worker、发布环境或业务枚举。
- 不引入微服务、消息队列、事件总线、第二套 UI 框架或新的全局状态基础设施。
- 不因为视觉稿新增天气供应商、定位权限、AI 会话表、消息保留策略或数据导出策略；这些均需独立的产品/接口/隐私决策。
- 不把 AI 的对话回复直接当成账单、日程、待办或行程正式记录；Proposal 必须经过既有或后续批准的确认流程。
- 不以概念图的像素距离、示例文案或占位天气数据替代响应式、可访问性、错误和网络失败验收。
- 不在当前承载 PR #33 merge commit 的本地 MOBILE-C3 checkout 上开始第一项实现；UIR 规划可按治理流程写入 canonical 状态，但在规划提交进入 Integration 或获得精确本地基线授权前不得启动 UIR-02。

## 3. 已确认的产品与视觉方向

### 3.1 用户端

- `[已确认]` 整体为温暖、克制、轻量的个人助手风格：暖白/浅暖灰底色，白色或略带紫调的内容面板，柔和紫色用于品牌主操作。
- `[已确认]` 视觉优先级是清晰的信息层级和快速完成任务，不使用大面积渐变、玻璃拟态或装饰性动效来承担信息表达。
- `[已确认]` 主导航固定为：首页、记录、计划、我的。AI 作为首页入口和独立页面，不强制占用根导航标签。
- `[已确认]` 首页不展示“已同步”常驻状态；同步异常仍可在需要时通过错误、冲突或设置入口反馈，不能把同步状态伪装成天气或问候内容。
- `[已确认]` 问候区显示日期、星期、城市和天气；小猫位于天气/问候区域内作为轻量插画，不单独新增一行。
- `[已确认]` 日期时间字段以按钮/字段触发选择器；日期使用日历，小时和分钟使用紧凑滚轮或可选择列表，用户不需要手动输入时间。
- `[设计建议]` 主要操作使用一处清晰的强调色，次级操作使用中性按钮或文本按钮；卡片只包裹真正独立的信息组，不把每一行都做成卡片。

### 3.2 管理端

- `[已确认]` 管理端保留 Vue Element Plus，不再引入用户端同款移动 UI 组件库。
- `[已确认]` 默认骨架为左侧导航 + 顶部上下文栏 + 主内容/表格 + 右侧详情抽屉；窄屏可以折叠左侧导航，但不能牺牲操作可达性。
- `[现状事实]` 管理员默认不能读取用户账单、日程、待办和行程正文；UI 仅呈现账号、容量、状态和脱敏审计信息。
- `[现状事实]` 容量上限可配置；暂停账号仍占容量，关闭账号释放容量，恢复必须重新检查容量。管理端页面不能用“暂停=释放名额”的文案或图形误导管理员。

## 4. 信息架构

### 4.1 用户端根导航

| 根入口 | 首要任务 | 典型内容 | 视觉重点 |
|---|---|---|---|
| 首页 | 了解今天并快速记录 | 问候/日期天气、快速记录、今日安排、最近记录、AI 入口 | 快速记录最醒目，天气和小猫合并为同一信息区 |
| 记录 | 查看和维护财务记录 | 账单列表、筛选、分类、账户、预算、草稿 | 金额层级清楚，筛选可收起，列表不堆叠卡片 |
| 计划 | 处理未来安排 | 日程、待办、提醒、时间线、行程入口 | 日期和状态可扫描，操作不依赖 hover |
| 我的 | 管理个人能力与设置 | 账户、分类、快捷指令、同步、设置、AI/帮助入口 | 设置按主题分组，危险操作在底部 |

桌面端可以将根入口渲染为侧栏或顶部导航，但页面语义、路由和返回规则保持一致。移动端根页显示底部导航，深层二级页隐藏根底部导航，避免与返回操作冲突。

### 4.2 AI 对话入口与页面

- 首页提供清晰但不抢占“快速记录”的 AI 入口；入口文案应说明“与 AI 助手对话”或同义含义。
- 独立 AI 页面提供消息列表、输入区、建议快捷项、发送中/失败/重试和 Proposal/草稿卡片。
- AI 回复可以是解释、建议或 Proposal；Proposal 必须展示目标业务类型、待确认字段、来源/时间上下文和“编辑/确认/拒绝”等动作。
- `[关键假设]` 第一阶段复用既有 AI Proposal/确认能力，新的多轮会话只作为设计能力，是否持久化会话历史由 API/数据保留决策决定。

### 4.3 二级页面分类

所有二级页面归入以下五类，进入实现前先确定所属类型：

1. 列表：筛选/分段、批量或行操作、空状态和新增入口。
2. 详情：状态摘要、核心字段、关联内容和危险操作。
3. 编辑：单列表单、字段校验、日期时间选择器、固定底部保存区。
4. 复杂详情：摘要、分段/标签、时间线或清单、局部编辑和关联对象。
5. 设置：按主题分组的开关/选择项、帮助说明、同步与隐私说明、底部危险区。

统一二级页原则：顶部约 52px 返回标题栏，内容区默认 16px 页面留白和模块间距，主要控件触控高度 44–48px；编辑页可使用固定底部操作区；复杂详情页不显示根底部导航。

## 5. 天气与 AI 的能力边界

### 5.1 天气

- `[设计建议]` 天气只承担首页问候区的轻量辅助信息，不成为新的根导航或独立业务模块。
- `[待确认]` 数据来源、城市来源（手动选择/账户设置/设备定位）、更新频率、时区和是否保存地点，必须由天气适配层和隐私决策确认。
- `[设计建议]` 天气适配层返回最小展示模型，例如城市、天气短文案、温度、更新时间和可选图标；页面不直接绑定供应商响应。
- `[已确认]` 获取失败、权限被拒绝、离线或额度受限时，首页退化为日期/星期，必要时保留城市设置入口，不阻塞快速记录和其他首页内容。
- `[禁止]` 不把失败原因、供应商字段、定位坐标或原始响应直接展示给用户；不在本次 UI 任务中新增真实外部服务配置。

### 5.2 AI 对话

- `[现状事实]` 当前 AI 领域已经有 Proposal/操作确认和服务端适配边界；浏览器不得直连 Provider，Provider 输出不得直接写业务表。
- `[设计建议]` 对话 UI 只管理展示状态：发送中、成功、失败、重试、流式/非流式占位和 Proposal 待确认；正式写入仍调用正式业务服务并记录审计。
- `[待确认]` 多轮会话是否落库、会话归属/隔离、历史保留时长、删除权、上下文范围、费用/预算和是否支持流式回复，不能由视觉稿决定。
- `[待确认]` 新对话 API、消息结构、幂等键、错误码和权限规则必须先同步 OpenAPI 与数据字典，再实施页面联调。
- `[禁止]` 不把“发送消息成功”当成“业务记录已创建”，不在输入框中保存密码、令牌或其他凭据，不以客户端隐藏按钮替代服务端权限校验。

## 6. 响应式与布局策略

| 宽度 | 用户端布局 | 管理端布局 | 必须检查 |
|---|---|---|---|
| 375px | 单列、底部导航、紧凑日期时间选择器、操作按钮可换行 | 侧栏折叠/抽屉、表格可横向滚动或转卡片 | 无横向溢出，长标签和键盘焦点可见 |
| 390px | 主要验收宽度，单列表单与天气问候区稳定 | 同上 | 首页、二级页、弹窗、日期时间滚轮 |
| 430px | 允许卡片内部双列摘要，但不改变主要信息顺序 | 允许更宽筛选行 | 弹层安全区、固定底部操作区 |
| 768px | 可使用双列摘要/列表详情，但表单仍可保持单列 | 侧栏可固定，表格和抽屉同时可用 | 返回、Back、滚动容器和抽屉宽度 |
| 1440px | 内容设置 max-width，避免大屏拉伸；可使用列表/详情双栏 | 左侧导航 + 表格 + 详情抽屉完整布局 | 键盘操作、缩放、无空白失衡 |

- 所有尺寸都使用 CSS 变量和流式尺寸；不能通过单个页面的负 margin 或固定宽度“修”溢出。
- 文字随系统设置放大至 200% 时，信息不依赖颜色或绝对定位表达，关键按钮仍可触达。
- 移动端弹窗、Action Sheet 和日期时间面板需考虑安全区、软键盘和滚动锁定；桌面端可使用居中弹层或锚点弹层，但语义相同。
- 桌面端表单建议限制在约 680–760px 内容宽度，复杂详情可以使用 2 栏；具体像素属于实现校准，不是视觉稿强制契约。

## 7. 可扩展性要求

实现必须保留下列扩展点，不要求首批全部启用：

- 语义化 design token：颜色、字体、间距、圆角、阴影、层级、动效和密度均可集中替换。
- 主题扩展：至少允许浅色基线、后续深色/高对比主题在不重写业务组件的情况下加入。
- 紧凑/舒适两种信息密度；默认移动端优先保证触控尺寸，桌面端可以由页面或用户设置选择密度。
- 页面头部的 `header`、筛选的 `filter`、状态的 `status` 和动作的 `action` slots；没有内容时不能留下空占位。
- 桌面 max-width、列表/详情双栏和抽屉宽度可配置，不把单列手机布局硬编码为所有尺寸。
- 弹窗可在确认弹窗、表单弹窗、底部 Sheet、全屏编辑四种形态间复用同一焦点、关闭和滚动策略。

## 8. 迁移原则与实施顺序

1. 先审计页面、路由、原生控件、现有弹窗、错误状态和测试，再冻结组件映射；不得凭截图大批量替换。
2. 先抽取 token 和基础组件，再改 App Shell、根导航和三个样板页面；样板页验收后按页面族迁移。
3. 复用现有 `AppDialog`、二级页面壳、`DateField`/`MonthField`/`DateTimeField` 和导航策略；除非任务契约明确允许，不新建平行体系。
4. 每次迁移保持路由、Store、API、序列化、校验、离线队列和权限行为；视觉变化与行为变化分开记录。
5. 先处理空、加载、错误、离线、冲突、无权限和未保存保护，再扩大页面覆盖；不能只验证有数据的成功态。
6. 第一项代码任务只建立 token、样式层/组件边界、主题/密度/slot 扩展点，并迁移一个低风险样板页；不得从设计图直接全站迁移。样板通过后再进入基础组件、壳层和页面族任务。
7. 开始代码前重新核验 PR #33 已进入当时的实际 Integration HEAD、合并后 CI 和既有设备证据，然后从核验基线新建独立 UIR 分支；不得在当前 `codex/mobile-c3-date-time-controls` checkout 直接开发。当前本地 merge commit 只证明本地 ancestry，不替代实施时的新鲜远端核验。
8. UI/产品/契约由 `5.6 Sol` 维护；每个 bounded implementation task 由 `5.6 Luna` 执行；主代理必须独立审查 diff、检查越界、运行适用验证。当前不使用 DeepSeek，也不能把任何模型完成消息作为验收证据。

## 9. 设计稿与实现契约的关系

- 概念图用于确认方向、层级、主要状态和交互路径，不是逐像素复制指令。
- 设计图中的示例姓名、金额、日期、天气、AI 文案和小猫插画都是占位内容，不能写入固定业务默认值或测试断言。
- 若图稿与现有 API、路由、数据字典、权限或离线语义冲突，以冻结契约和本基线的边界为准，并在对应 UIR 任务中记录冲突。
- 新增真实能力（天气、持久化会话、流式回复、通知、定位）必须先有独立的 API/数据/隐私决策；完成图稿不等于获得这些变更的授权。
