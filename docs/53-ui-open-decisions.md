## D1 天气城市来源

- 现状事实：账户模型/UI 当前未形成已批准的天气城市字段；首页概念要求城市和天气，但没有定位权限契约。
- 推荐：账户城市作为稳定来源，并允许用户手动选择/修改；未设置时只显示日期/星期和“设置城市”入口。首期不请求设备定位。
- 替代：设备定位优先，拒权后手动选择；或完全手动、仅保存在设备偏好。
- 用户体验：稳定、跨设备一致且无首次权限打断；代价是首次设置一步操作，旅行时不会自动切城。
- 技术影响：未来可能需要账户偏好字段/API；UIR-06 只能做无数据占位，真实接入需独立契约。
- 隐私安全：不采集精确坐标；城市属于个人偏好，应按 userId 隔离，日志不记录地址/坐标。
- 成本/依赖：城市选择本身无 Provider 成本；地名搜索若引入第三方需另审。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-06 可使用降级占位；真实天气或最迟 UIR-09 前。

## D2 天气供应商、更新、缓存与降级

- 现状事实：无已批准天气 Provider、适配器、费用或 SLA；架构要求第三方通过适配层并可降级。
- 推荐：服务端 WeatherProviderAdapter；同城 30 分钟缓存，页面进入/恢复前台时仅在过期后刷新；超时约 3–5 秒；失败、离线、限额时隐藏温度/天气，仅保留日期星期和可重试/设置城市入口。原始 Provider 响应不持久化。
- 替代：客户端直连免费天气服务；或每日固定两次批量更新。客户端直连会暴露 key/Provider 细节，不推荐。
- 用户体验：信息可能最多延迟 30 分钟，但首页稳定且天气失败不阻塞快速记录。
- 技术影响：需新增适配层、最小 DTO、缓存和观测；不得在 UIR 页面任务内隐式实现。
- 隐私安全：Provider 只接收城市级查询，不发送用户 ID、账单或精确位置；日志仅记录脱敏城市标识、状态和延迟。
- 成本/依赖：取决于供应商免费额度/商用条款；选型前需核验中国大陆可用性、许可证、限额与数据区域。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-09 前；Provider/生产配置需独立批准。

## D3 AI 对话历史是否持久化

- 现状事实：当前 `AiView` 是请求/Proposal 流程，不是已批准的持久化多轮聊天；已有 AiRequest/Proposal 有各自保留边界。
- 推荐：首期不新增聊天历史持久化。页面保留当前会话内存态或展示现有请求/Proposal；刷新后不承诺恢复多轮对话。
- 替代：持久化完整多轮会话；或仅持久化用户明确收藏的摘要。
- 用户体验：隐私清晰、实现快，但跨刷新/设备不能继续对话；可用“保存为草稿/Proposal”保留有价值结果。
- 技术影响：无需新表/API；完整历史方案会引入会话、消息、分页、删除、导出和迁移。
- 隐私安全：减少敏感正文存储和跨用户泄露面；当前输入/Proposal 仍遵循既有保留规则。
- 成本/依赖：无新增存储；多轮历史会增加存储和上下文 token 成本。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-09 前。

## D4 AI 会话与消息隔离、保留和删除

- 现状事实：产品要求 userId 强隔离，管理员默认不能读业务正文；尚无会话/消息 schema 或删除策略。
- 推荐：如未来持久化，所有会话/消息以 userId 强制归属；管理员只见脱敏运行元数据；用户可删除单会话和全部历史；删除同步清理搜索索引/缓存；默认保留期建议 30 天，但须与既有 AiRequest/Proposal 规则和 Provider 条款统一后再批准。
- 替代：会话长期保留直到用户删除；或仅保存不可逆摘要。长期默认保留风险更高。
- 用户体验：可控、可解释；自动到期需明确提示，删除应说明正式业务记录不会随聊天删除。
- 技术影响：需要数据字典、OpenAPI、级联/异步清理策略、审计和隔离测试。
- 隐私安全：必须覆盖 IDOR、跨用户分页、导出、删除、备份保留及 Provider 侧保留；原文不得进入普通日志。
- 成本/依赖：数据库/备份容量和删除治理成本；Provider 保留条款可能成为门禁。
- 阻塞 UIR-02：否。
- 最晚确认：任何会话 schema/API 任务前，且早于 UIR-09 真实多轮接入。

## D5 AI 上下文、成本与降级

- 现状事实：现有 ADR 冻结白名单、安全阈值、超时/重试/熔断和自然月元数据；未批准聊天上下文读取个人业务正文或固定金额上限。
- 推荐：默认只发送当前用户消息、用户显式选中的对象和最小系统指令；不自动拉取全部账单/日程。服务端设置消息/字符/token 上限与自然月用量观测；超限或 Provider 不可用时退化为单轮建议/本地快捷模板，并保留输入。
- 替代：自动检索用户全部近期数据；或固定最近 N 条消息。自动全量上下文不推荐。
- 用户体验：回答可能少些“懂你”，但授权边界清楚；UI 应显示本次引用的上下文并允许移除。
- 技术影响：需服务端上下文选择器、白名单、预算门禁、截断摘要和可观测性；UIR-09 前另立契约。
- 隐私安全：最小化传输，敏感字段不越白名单；不得将一个用户上下文用于另一个用户或管理员会话。
- 成本/依赖：token 成本可控；摘要/检索会增加模型或存储依赖。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-09 前。

## D6 AI 流式响应

- 现状事实：当前请求/Proposal API 与 UI 以完成式响应为主；没有已冻结 SSE/WebSocket 流协议、取消或断线恢复语义。
- 推荐：首期非流式，使用清晰 loading、超时、保留输入和重试；等多轮 API、幂等、取消、代理超时和日志边界稳定后再评估 SSE。
- 替代：SSE 单向流式；WebSocket 双向会话。若未来需要，SSE 比 WebSocket 更符合当前单体架构。
- 用户体验：首字等待较长但状态可靠；流式更即时，却会带来中断、半条消息和重试困惑。
- 技术影响：非流式不改协议；流式需 OpenAPI/事件契约、网关/Nginx buffering、取消、拼接、测试。
- 隐私安全：流片不得写普通日志或在错误中回显原始内容；断线重试不得重复生成正式操作。
- 成本/依赖：流式不必降低 token 成本，增加测试与运维复杂度。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-09 前。

## D7 桌面端根导航

- 现状事实：当前用户端桌面主要是顶部 SiteHeader；移动端底部四根导航已稳定。已确认桌面需保留扩展能力，但侧栏/顶部尚未最终签收。
- 推荐：`>= 1024px` 使用可收窄的左侧导航，固定首页/记录/计划/我的；顶部仅保留页面上下文和全局状态。移动/平板继续底部导航，路由语义不变。
- 替代：继续顶部导航；或 768px 起侧栏。顶部实现成本低，侧栏更适合未来宽屏列表/详情。
- 用户体验：侧栏提升宽屏可发现性并为多模块扩展留空间；切换断点需避免导航突然跳动。
- 技术影响：UIR-05 修改 shell/layout，不改 router；需五档和 200% 文本验证。
- 隐私安全：无新增数据；全局状态不得显示敏感正文。
- 成本/依赖：无第三方依赖。
- 阻塞 UIR-02：否，UIR-02 只预留 slot/max-width。
- 最晚确认：UIR-05 前。

## D8 首期主题与密度开关

- 现状事实：规范要求保留主题/密度扩展点；尚无用户偏好存储或公开设置入口。
- 推荐：UIR-02 实现内部 `data-ui-theme="default"` 与 `data-ui-density="comfortable"` 覆盖契约，并提供 compact token；首期不显示开关、不持久化偏好。
- 替代：首期直接暴露密度；或同时暴露暗色主题。两者都会扩大全站状态矩阵。
- 用户体验：首期一致稳定；高级用户暂不能切换。后续开放无需重写组件。
- 技术影响：纯 CSS hook，不改 Store/API；公开开关时再决定本地或账户持久化。
- 隐私安全：无敏感影响；避免把偏好同步误当业务数据。
- 成本/依赖：无第三方依赖；暗色主题会显著增加视觉回归成本。
- 阻塞 UIR-02：否；可按推荐冻结实现边界。
- 最晚确认：是否公开最迟 UIR-10 前；UIR-02 只实现隐藏扩展点。

## D9 小猫插画资产、许可与无障碍

- 现状事实：当前有 CSS/组件化 AssistantMark，但没有经本决策确认的正式小猫资产与许可证记录。
- 推荐：使用项目自有、委托创作或明确允许商用修改/分发的 SVG；在 THIRD_PARTY_NOTICES/资产清单记录作者、来源、版本和许可。纯装饰时 `aria-hidden="true"`、不可聚焦；若表达天气状态，使用邻近文本而非依赖插画替代文本。
- 替代：自绘 CSS 图形；或购买商业插画包。CSS 无外部许可但表现力有限。
- 用户体验：品牌一致、加载轻；窄屏可缩小/隐藏但不挤压日期天气和快速记录。
- 技术影响：优化 SVG、固定 viewBox、禁止内联脚本/外链资源；需要资产快照和尺寸测试。
- 隐私安全：本地静态资产不发第三方请求；外部 CDN/跟踪像素禁止。
- 成本/依赖：自有/开源可低成本；付费资产需采购授权，当前任务不购买。
- 阻塞 UIR-02：否。
- 最晚确认：UIR-06 可用明确标记的临时占位；正式交付最迟 UIR-09 前。

## 冻结边界

仅从产品决策依赖看，UIR-02 可以在九项决策仍为“建议、未批准”时开始，因为它只建立语义 token、隐藏扩展点、插槽和 ChangePassword 样板；但当前 Git 交付状态仍是 `PLANNING_NOT_IN_INTEGRATION`，在规划提交进入 Integration 或精确本地 SHA 获单独授权前不得创建分支或调用 Luna。Luna 不得借推荐内容实现天气、AI 会话、Provider、定位、偏好持久化、桌面导航或正式插画。D7 必须在 UIR-05 前签收；D1–D6、D9 必须在 UIR-09 或相应独立 API/数据任务前签收。
