## 2. Existing versus new persistence boundary

The existing PR18 AiRequest baseline fields must remain unchanged:

~~~text
AiRequest.locale
AiRequest.timeZoneId
~~~

PR19 must not remove, rename, retype or stop normal persistence of these fields,
must not add migration changes for them, and must not duplicate them into
recovery/retention fields.

The only newly authorized persisted body content is:

~~~text
originalUserInput      String? @map("original_user_input") @db.VarChar(2000)
originalInputExpiresAt DateTime? @map("original_input_expires_at")
~~~

A minimal expiry index is permitted. At claim creation:

~~~text
originalUserInput = validated request.userInput
originalInputExpiresAt = createdAt + 30 days
~~~

No recovery/retention persistence may be added for:

~~~text
requestType
locale
timeZoneId
currentDateTime
currency
allowedCategoryLabels
explicitSelectedContext
~~~

For locale and timeZoneId, existing baseline columns remain but no second
recovery/retention copy may be added. For all other fields, do not add a
dedicated column, JSON envelope, raw request object or recovery copy.

The following are prohibited:

~~~text
originalInputJson
requestEnvelopeJson
providerInputJson
whole-input persistence
raw HTTP body persistence
raw prompt envelope persistence
raw request envelope persistence
headers/cookies/credentials/tokens persistence
raw Provider request/response persistence
~~~

inputFingerprint is not recoverable original input. Failed, unresolved and
recovered requests retain original input until expiry or earlier deletion.
Success may clear only the two new fields inside the winning atomic success
transaction. Replay and retry must not extend expiry. User/account deletion
must clear or cascade-delete them.

### Migration boundary

The PR19 migration may only:

~~~text
ADD original_user_input
ADD original_input_expires_at
ADD minimal expiry index
~~~

It must not alter locale, time_zone_id or any unrelated AiRequest field.

## 4. AiRequest state machine

### New claim

~~~text
status = CLAIMED
startedAt = NULL
completedAt = NULL
~~~

Existing locale and timeZoneId continue their normal baseline persistence. No
Provider attempt exists yet.

### Pre-Adapter failures

~~~text
FEATURE_DISABLED -> CLAIMED -> FAILED
BUDGET_BLOCKED   -> CLAIMED -> FAILED
CIRCUIT_OPEN     -> CLAIMED -> FAILED
~~~

Each transition is conditional on the current request, current user and
status = CLAIMED, and sets status, completedAt, stable failureCategory and the
existing public failureCode:

~~~text
FEATURE_DISABLED -> AI_DISABLED
BUDGET_BLOCKED   -> AI_BUDGET_BLOCKED
CIRCUIT_OPEN     -> AI_CIRCUIT_BREAKER_BLOCKED
~~~

These paths leave startedAt = NULL, retain original input/expiry, create zero
attempts, make zero Adapter/Stub calls, perform zero retry and write zero
Breaker samples. A lost conditional transition is resolved by re-reading the
persisted state without overwriting it.

### Provider entry

Only after all gates allow, atomically establish:

~~~text
CLAIMED -> RUNNING
AiRequest.startedAt = logicalNow
AiProviderAttempt.attemptNo = 1
AiProviderAttempt.status = RUNNING
AiProviderAttempt.startedAt = logicalNow
~~~

The boundary must complete before the Adapter call. If it fails, do not call the
Adapter or create another attempt. AiRequest.startedAt is the first
Provider-execution clock.

Retry must not modify AiRequest.startedAt; attempt #2 has its own startedAt.
Only attempt numbers 1 and 2 are allowed, with at most one RUNNING attempt.

### Terminal states

The winning attempt and request are terminalized atomically for success or
failure. CANCELLED, if encountered, must never restart Provider work.

## 5. Idempotency and recovery

The idempotency identity is:

~~~text
same user + same Idempotency-Key + same inputFingerprint
~~~

User/key/fingerprint mismatch returns an existing conflict without leaking
persisted request data.

### SUCCEEDED

Return the persisted successful result with no gate evaluation, Adapter/Stub
call, retry or new attempt.

### FAILED

Replay the persisted failure through the shared failure mapper with no gate
evaluation, Adapter/Stub call, retry or new attempt. Replay must not extend the
original expiry.

### Fresh CLAIMED

If createdAt > now - 60 seconds, return IDEMPOTENCY_CONFLICT / HTTP 409. There
must be zero second Feature/Budget/Breaker execution, Adapter/Stub call, attempt,
retry or Breaker sample.

### Stale CLAIMED

If createdAt <= now - 60 seconds, conditionally perform:

~~~text
CLAIMED -> FAILED
failureCategory = STALE_CLAIMED_RECOVERY
failureCode = INTERNAL_ERROR
completedAt = now
~~~

Preserve original input and expiry. Create no attempt, call no Adapter/Stub,
execute no gates and write no Breaker sample. On race loss, re-read and resolve
the current state.

### Fresh RUNNING

If startedAt > now - 60 seconds, return IDEMPOTENCY_CONFLICT / HTTP 409. Do not
re-run gates, create an attempt or call the Adapter. Never use createdAt as the
RUNNING recovery clock.

### Stale RUNNING

If startedAt <= now - 60 seconds, the same-key create path must trigger runtime
stale recovery:

~~~text
AiRequest: RUNNING -> FAILED
failureCategory = STALE_RUNNING_RECOVERY
failureCode = AI_PROVIDER_TIMEOUT
completedAt = now
~~~

The matching RUNNING AiProviderAttempt must be conditionally terminalized in
the same transaction or atomic boundary. Already-terminal attempts must not be
overwritten. Then replay the persisted timeout through the shared mapper.

Recovery creates no new attempt, Adapter call, gate evaluation or duplicate
Breaker sample.

### RUNNING with NULL startedAt

The state

~~~text
AiRequest.status = RUNNING
AiRequest.startedAt = NULL
~~~

is inconsistent. It must not be classified as fresh or stale RUNNING and must
not use createdAt as a fallback. It must not re-run Feature/Budget/Breaker gates,
create an attempt, call Adapter/Stub or write a Breaker sample.

Conditionally recover:

~~~text
AiRequest: RUNNING -> FAILED
failureCategory = INCONSISTENT_RUNNING_STATE
failureCode = INTERNAL_ERROR
completedAt = now
~~~

Preserve original input/expiry. If a matching attempt is still RUNNING,
conditionally terminalize it in the same boundary:

~~~text
RUNNING -> FAILED
failureCategory = INCONSISTENT_RUNNING_STATE
completedAt = now
~~~

Already-terminal attempts must not be overwritten. Return/throw INTERNAL_ERROR
through the shared mapper. On race loss, re-read and apply normal existing-state
rules. No schema change or new public error code is permitted.

### CANCELLED

Never restart Provider work. Return deterministic non-success/idempotency
conflict behavior with no Adapter call or new attempt.

## 6. Exact request-time Feature Gate

Every new logical Proposal create request loads fresh database flags with
loadDatabaseFeatureFlags(prisma) and calls the existing three-argument shared
resolver:

~~~text
resolveFeatureFlag(flag, environment, databaseFlags)
~~~

The Router must not implement its own environment parser, JSON parser, database
flag parser or duplicate policy.

Required flags:

~~~text
proposalEnabled = resolveFeatureFlag("v15.ai.proposal", environment, databaseFlags)
fakeProviderEnabled = resolveFeatureFlag("v15.ai.fakeProvider", environment, databaseFlags)
liveProviderEnabled = resolveFeatureFlag("v15.ai.liveProvider", environment, databaseFlags)
~~~

Only this combination permits Fake execution:

~~~text
proposalEnabled = true
fakeProviderEnabled = true
liveProviderEnabled = false
~~~

Every Feature Gate fail-closed outcome, including missing/malformed environment,
missing/malformed DB flag and DB read failure, is exactly:

~~~text
failureCategory = FEATURE_DISABLED
failureCode = AI_DISABLED
AiRequest CLAIMED -> FAILED
startedAt = NULL
zero Adapter/Stub calls
zero Provider attempts
zero retry
zero Breaker sample
~~~

Persisted replay and same-key recovery do not re-evaluate Feature Gate.

## 9. Complete Circuit Breaker state machine

The Breaker is runtime-only, has no persistence schema and does not restore
state after process restart.

~~~text
window = last at most 20 logical-request samples
sample types = SUCCESS | TECHNICAL_FAILURE | NON_TECHNICAL
technical categories = NETWORK_ERROR | TIMEOUT | HTTP_429 | HTTP_5XX
OPEN when technical count >= 5 AND technical rate >= 50%
~~~

Each logical request contributes at most one final sample. There are no
per-attempt samples.

In CLOSED:

~~~text
success/uncertain -> SUCCESS sample -> CLOSED
nontechnical     -> NON_TECHNICAL sample -> CLOSED
technical        -> TECHNICAL_FAILURE sample -> OPEN if threshold met
~~~

Pre-Adapter failures produce zero samples.

For the first 60 seconds in OPEN, block requests with zero Adapter, attempt and
sample, and persist CLAIMED -> FAILED as:

~~~text
failureCategory = CIRCUIT_OPEN
failureCode = AI_CIRCUIT_BREAKER_BLOCKED
startedAt = NULL
~~~

After 60 seconds, transition to HALF_OPEN. Exactly one logical request gets
the probe permit. Concurrent losers are blocked with zero Adapter, attempt and
sample. The probe may retry normally up to two attempts, and retry does not
acquire another probe permit.

Final probe result:

~~~text
TECHNICAL_FAILURE -> OPEN and restart 60-second interval
SUCCESS/UNCERTAIN -> CLOSED and clear old rolling samples
NON_TECHNICAL     -> CLOSED and clear old rolling samples
~~~

At most one final probe sample is recorded. Late completions cannot write or
alter Breaker state. Process restart yields CLOSED with an empty window.

## 10. Timeout, retry and late-result fence

Each Adapter invocation has a 15-second timeout. AbortSignal is optional; the
correctness requirement is the settlement fence.

~~~text
maximum retries = 1
maximum attempts = 2
retry delay = 100ms
retryable = NETWORK_ERROR | TIMEOUT | HTTP_429 | HTTP_5XX
~~~

Attempt #1 retryable failure terminalizes attempt #1, leaves the request RUNNING,
waits 100ms, verifies the request is still RUNNING, then creates attempt #2
before the second call. If the request is no longer RUNNING, no attempt #2 or
Adapter call is allowed.

Each Adapter invocation has exactly one accepted terminal settlement. Once a
timeout wins, later resolve/reject is ignored and must not modify the attempt,
request, Proposal, original input, failure code, retry state, Breaker sample or
Breaker state.

## 11. Failure persistence and business-write boundary

Initial failure and replay use the same mapper:

~~~text
persisted failureCode -> shared ApiException/HTTP mapper
~~~

Known codes remain distinct, including:

~~~text
AI_DISABLED
AI_BUDGET_BLOCKED
AI_CIRCUIT_BREAKER_BLOCKED
AI_PROVIDER_TIMEOUT
AI_PROVIDER_NETWORK_ERROR
AI_SCHEMA_VALIDATION_ERROR
AI_DOMAIN_VALIDATION_ERROR
AI_MALFORMED_OUTPUT
AI_PROVIDER_ERROR
INTERNAL_ERROR
~~~

Replay preserves public code, equivalent HTTP semantics, stable sanitized
message and original expiry. It never collapses known codes into
AI_PROVIDER_ERROR.

For an unknown or corrupt persisted failureCode, fail closed through the
existing INTERNAL_ERROR public mapping. Do not expose database, storage or
internal details. The replay performs zero Feature Gate, Budget Gate or Breaker
re-evaluation; zero Adapter/Stub call; zero retry; zero new attempt; and zero
new Breaker sample. It must not extend originalInputExpiresAt.
No new public ApiErrorCode is permitted.

Provider output must be schema validated, domain validated and normalized before
Proposal creation. Provider output never directly writes formal business tables.

~~~text
Accept Proposal != Final Confirm Business Write
~~~

Formal writes require explicit final user confirmation and existing Domain
Services.
